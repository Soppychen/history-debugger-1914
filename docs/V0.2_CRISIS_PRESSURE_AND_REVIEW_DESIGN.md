# 《历史现场调试器：1914》v0.2 设计文档

版本目标：危机压迫与复盘增强版  
面向对象：程序、美术、策划  
状态：执行规格草案  
日期：2026-06-03

---

## 1. 版本定位

v0.2 不以扩充大量新历史内容为核心，而是强化现有 12 回合七月危机的体验密度。

本版本目标是让玩家明确感受到：

> 每一次推进时间，都意味着某些历史窗口正在关闭。

当前 v0.1 已经验证了基础循环：

- 读取 JSON 数据
- 初始化变量
- 展示时间线、情报卡、干预卡
- 使用卡牌修改变量
- 触发风险与反噬
- 推进回合
- 判定结局
- 生成结算报告

v0.2 要解决的问题是：

- 玩家容易把游戏理解成“慢慢选卡”。
- 未来事件压力不够显性。
- 卡牌过期和错过窗口的痛感不足。
- 不可逆节点缺少足够强的系统反馈。
- 结算报告还需要更好解释“为什么走向这个结局”。

---

## 2. 设计原则

### 2.1 不急着加大地图或新 Case

v0.2 仍聚焦 1914 七月危机。

不新增第二个历史案件，不做自由历史改写，不做复杂地图操作。

### 2.2 新事件必须服务玩法压力

允许新增事件，但事件必须属于以下类型之一：

- 时间窗口事件：某张卡即将失效。
- 误判事件：变量信息不足导致行动风险上升。
- 不可逆事件：历史进入下一阶段，部分路线永久关闭。
- 分支压力事件：玩家前期选择改变后续风险形态。

不要新增只用于阅读的历史百科式内容。

### 2.3 玩家不是上帝

所有新增功能都应继续遵守项目核心原则：

- 玩家只能通过 plausible historical mechanisms 干预。
- 每个干预都应该有代价、限制或反噬。
- 历史不是单按钮改写，而是系统状态被逐步推向不同结局。

---

## 3. v0.2 核心体验循环

v0.2 的每回合体验应调整为：

```txt
回合开始
→ 危机简报
→ 查看即将触发事件
→ 阅读情报并更新判断
→ 选择有限干预
→ 查看行动后果与反噬
→ 推进时间
→ 查看时间推进报告
→ 触发或避免不可逆节点
→ 进入下一回合
```

玩家每回合都应该能回答三个问题：

1. 本回合最危险的风险是什么？
2. 如果我推进时间，会错过什么？
3. 我刚才的行动具体改变了哪些变量和窗口？

## 4. 功能模块一：每回合危机简报

### 4.1 目标

玩家进入每回合时，先理解局势，而不是直接进入卡牌选择。

危机简报要把玩家从“卡牌商店心态”切换成“危机处理心态”。

### 4.2 程序需求

新增组件：

```txt
TurnBriefingModal
```

触发规则：

- 每回合开始时自动弹出一次。
- 玩家可以关闭。
- 玩家可通过当前回合面板再次打开。

建议数据来源：

```txt
public/data/timeline_1914.json
```

建议为 timeline turn 增加字段：

```ts
interface TurnBriefing {
  briefingTitle: string;
  briefingText: string;
  keyRisks: string[];
  focusVariableIds: string[];
  expiringCardIds: string[];
  upcomingEventIds: string[];
}
```

示例：

```json
{
  "turn": 5,
  "briefing": {
    "briefingTitle": "倒计时开始",
    "briefingText": "奥匈最后通牒即将发出。英国红线仍不清晰，俄国动员压力开始上升。",
    "keyRisks": [
      "若奥匈强硬度维持高位，最后通牒将更难被塞尔维亚接受。",
      "若英国红线继续模糊，德国可能低估英国介入风险。"
    ],
    "focusVariableIds": [
      "austrian_hardline",
      "british_redline_clarity",
      "russian_mobilization_pressure"
    ],
    "expiringCardIds": ["C10"],
    "upcomingEventIds": ["ultimatum_sent", "serbian_reply_deadline"]
  }
}
```

### 4.3 UI 内容

危机简报至少显示：

- 回合编号
- 日期范围
- 简报标题
- 80 字以内局势描述
- 2-3 条关键风险
- 重点变量
- 即将失效卡牌
- 即将触发事件

### 4.4 美术需求

美术提供：

- 12 张回合危机图，横向或 16:9。
- 用于简报顶部或侧边。
- 风格：旧地图、档案、红线、外交电报、军事时间表。

不需要大场景战争插画，重点是“档案室里的危机感”。

## 5. 功能模块二：即将触发事件队列

### 5.1 目标

让玩家看到未来 1-3 回合的压力。

玩家不是只看当前状态，而是看到多条历史火线正在逼近。

### 5.2 程序需求

新增组件：

```txt
UpcomingEventsPanel
```

位置建议：

- 桌面端：中间主面板或时间线旁。
- 移动端：当前回合信息下方，可折叠。

建议新增事件数据结构：

```ts
interface CrisisEvent {
  id: string;
  title: string;
  turn: number;
  description: string;
  eventType:
    | "diplomatic_window"
    | "ultimatum"
    | "mobilization"
    | "media_pressure"
    | "irreversible"
    | "war_threshold";
  effectsPreview: Array<{
    variableId: string;
    delta: number;
  }>;
  relatedCardIds: string[];
  interventionWindow?: {
    startTurn: number;
    endTurn: number;
  };
  irreversibleNodeId?: string;
}
```

事件可放在：

```txt
public/data/timeline_1914.json
```

或独立为：

```txt
public/data/crisis_events_1914.json
```

如果独立建文件，需要同步更新数据加载和验证脚本。

### 5.3 UI 内容

每条事件显示：

- 还有几回合触发
- 事件标题
- 事件类型图标
- 可能影响变量
- 关联干预卡
- 是否即将关闭干预窗口

示例：

```txt
1 回合后：奥匈最后通牒发出
影响：奥匈强硬度 +8，塞尔维亚妥协度 -6
干预窗口：C10 本回合后失效
```

### 5.4 美术需求

提供事件类型图标：

- 倒计时
- 外交窗口
- 最后通牒
- 动员
- 舆论升温
- 不可逆节点
- 战争阈值

建议尺寸：

```txt
64x64 png 或 svg
```

## 6. 功能模块三：卡牌状态系统增强

### 6.1 目标

卡牌不再只是“可用 / 不可用”，而是表达历史窗口的流失。

### 6.2 程序需求

扩展卡牌状态计算。

建议类型：

```ts
type CardState =
  | "available"
  | "expiring"
  | "missed"
  | "locked"
  | "ap_insufficient"
  | "used"
  | "event_locked";
```

状态规则：

- `available`：满足 AP、回合、requirements。
- `expiring`：当前回合等于 `turn_max`，且仍可使用。
- `missed`：当前回合超过 `turn_max`。
- `locked`：requirements 不满足。
- `ap_insufficient`：requirements 满足但 AP 不足。
- `used`：本局已使用，当前规则仍是一局一次。
- `event_locked`：不可逆节点触发后关闭该卡。

### 6.3 UI 文案

卡牌需要显示明确原因。

示例：

```txt
即将过期：若推进时间，此卡将失效。
已错过：最后通牒已经正式发出，文本无法再修改。
被事件锁死：俄国总动员已启动，外交延迟窗口关闭。
条件不足：需要外交信任度 ≥ 45。
AP 不足：需要 2 AP，当前剩余 1 AP。
```

### 6.4 美术需求

卡牌视觉状态：

- 普通：现有卡面。
- 即将过期：橙色边框、倒计时标记。
- 已错过：低饱和灰色、斜向归档线。
- 事件锁死：红色锁章、不可逆标记。
- AP 不足：按钮灰化，但内容仍可读。

动效建议：

- 即将过期：轻微边框脉冲。
- 已错过：无动画，保持冷静克制。
- 事件锁死：触发时短暂盖章动画。

## 7. 功能模块四：不可逆节点系统

### 7.1 目标

让玩家明确感到：历史已经进入下一阶段，部分路线永久关闭。

### 7.2 第一批不可逆节点

v0.2 建议至少实现 5 个，优先 6 个：

1. 最后通牒正式发出
2. 塞尔维亚拒绝核心条款
3. 奥匈宣战
4. 俄国总动员
5. 德国最后通牒
6. 德国入侵比利时 / 英国参战路径打开

### 7.3 程序需求

建议新增数据文件：

```txt
public/data/irreversible_nodes_1914.json
```

建议类型：

```ts
interface IrreversibleNode {
  id: string;
  title: string;
  triggerTurn?: number;
  conditions: Requirement[];
  effects: Effect[];
  lockedCardIds: string[];
  unlockedCardIds: string[];
  variableImpactSummary: string[];
  reportText: string;
  visual?: {
    image?: string;
    caption?: string;
    stamp?: string;
  };
}
```

引擎规则：

- 推进回合后检查不可逆节点。
- 用卡后如满足条件，也可检查。
- 同一节点一局只触发一次。
- 触发后写入 `triggeredNodeIds`。
- 触发后应用 effects。
- 触发后关闭 `lockedCardIds`。
- 触发后解锁 `unlockedCardIds`。
- 触发后写入 action log。

### 7.4 新增组件

```txt
IrreversibleNodeModal
```

弹窗显示：

- 节点标题
- 节点说明
- 变量影响
- 关闭窗口
- 新解锁卡牌
- 历史系统评语

示例：

```txt
不可逆节点已触发：俄国总动员

影响：
- 军事时间表刚性 +12
- 德国风险判断 -8
- 全面战争概率 +10

关闭窗口：
- C21 延迟动员沟通
- C22 低调外交协调

系统评语：
德国总参谋部开始接管政治节奏。
```

### 7.5 美术需求

提供：

- 6 张不可逆节点图。
- 1 个 `IRREVERSIBLE` 红色印章。
- 时间线红锁状态。
- 节点触发盖章动效设计。

风格：

- 红色不宜大面积铺满。
- 重点是官方档案被盖上“不可逆”印章的感觉。

## 8. 功能模块五：推进回合报告

### 8.1 目标

推进时间必须有反馈，让玩家知道自己刚刚放弃了哪些可能性。

### 8.2 程序需求

新增组件：

```txt
TimeAdvanceReportModal
```

触发规则：

- 点击推进回合后，先结算当前回合压力。
- 然后展示推进报告。
- 玩家确认后进入下一回合简报。

报告数据建议由 `advanceTurn` 返回：

```ts
interface TimeAdvanceReport {
  fromTurn: number;
  toTurn: number;
  daysAdvanced?: number;
  dateFrom: string;
  dateTo: string;
  defaultPressureChanges: VariableDelta[];
  specialRuleChanges: VariableDelta[];
  expiredCardIds: string[];
  triggeredNodeIds: string[];
  unlockedCardIds: string[];
  warProbabilityDelta: number;
  summary: string;
}
```

### 8.3 UI 内容

报告至少显示：

- 时间推进了几天
- 系统压力变化
- specialRules 触发情况
- 失效卡牌
- 不可逆节点
- 战争概率变化
- 一句冷静的系统总结

示例：

```txt
时间推进：3 天

系统压力：
- 俄国动员压力 +7
- 军事时间表刚性 +4
- 外交信任度 -5

窗口关闭：
- C10 调整最后通牒措辞 已失效

风险提示：
最后通牒文本已无法修改，后续只能处理其后果。
```

### 8.4 美术与音效需求

美术：

- 档案翻页视觉
- 日历推进视觉
- 红线向前推进的小动效

音效：

- 低沉电报声
- 打字机敲击
- 文件盖章

## 9. 功能模块六：情报卡价值增强

### 9.1 目标

情报卡不只是阅读内容，而是改变玩家对局势的判断。

### 9.2 程序需求

为情报卡增加 `reveals`。

建议类型：

```ts
type VariableVisibility = "hidden" | "unknown" | "rough" | "range" | "exact";

interface IntelReveal {
  variableId: string;
  visibility: VariableVisibility;
  range?: [number, number];
  confidence?: number;
  note?: string;
}
```

示例：

```json
{
  "id": "I12",
  "title": "英国内阁讨论摘要",
  "reveals": [
    {
      "variableId": "british_redline_clarity",
      "visibility": "range",
      "range": [35, 50],
      "confidence": 0.7
    }
  ]
}
```

变量面板显示：

```txt
英国红线清晰度：约 35—50
来源：I12 英国内阁讨论摘要
```

### 9.3 第一批接入范围

v0.2 至少让 5 张情报卡具备 reveals：

- 英国红线清晰度
- 德国风险判断
- 俄国动员压力
- 外交信任度
- 媒体煽动度

### 9.4 美术需求

先做 4 种情报卡模板：

- 外交电报
- 报纸剪报
- 内阁会议纪要
- 密件档案

每张模板可以复用，不要求每张情报卡独立插图。

## 10. 功能模块七：结算报告增强

### 10.1 目标

结算报告不只是胜负弹窗，而是历史事故调查报告。

玩家结束一局后，应能理解：

- 本局为什么进入这个结局。
- 哪些变量起了关键作用。
- 哪些行动有效。
- 哪些窗口被错过。

### 10.2 程序需求

扩展 ending report 生成逻辑。

新增报告模块：

```ts
interface EnhancedEndingReport {
  causalChains: string[];
  keyActions: string[];
  missedWindows: string[];
  irreversibleNodesTriggered: string[];
  finalVariableHighlights: Array<{
    variableId: string;
    value: number;
    reason: string;
  }>;
}
```

### 10.3 报告结构

结算报告建议显示：

```txt
1. 结局标题
2. 评级
3. 历史可信度
4. 最终变量摘要
5. 关键因果链
6. 玩家关键行动
7. 错过窗口
8. 不可逆节点
9. 系统评语
10. 分享短句
```

关键因果链示例：

```txt
英国红线模糊
→ 德国低估介入风险
→ 比利时问题升级
→ 全面战争概率突破临界
```

错过窗口示例：

```txt
C10 调整最后通牒措辞在第 5 回合后失效。
俄国总动员触发后，低调外交协调窗口关闭。
```

### 10.4 美术需求

做一版可截图分享的报告布局。

要求：

- 档案报告感。
- 结局印章明显。
- 手机竖屏截图可读。
- 最终变量摘要紧凑。
- 分享短句位置醒目但不轻浮。

## 15. 试玩验证问题

v0.2 完成后，内测应重点观察：

1. 玩家是否知道每回合该关注什么？
2. 玩家是否能理解为什么某张卡失效？
3. 玩家是否会在推进回合前犹豫？
4. 不可逆节点触发时，玩家是否感到局势进入新阶段？
5. 玩家是否能在结局后说出自己在哪几个节点失控？
6. 玩家是否愿意重开尝试另一条路线？
7. 玩家是否会只盯着战争概率，而忽略可信度和代价？

## 16. v0.2 验收标准

v0.2 完成标准：

- 玩家进入每回合都会看到危机简报。
- 玩家始终能看到未来 1-3 个即将发生的事件。
- 至少 10 张卡会出现“即将过期 / 已错过”状态。
- 至少 5 个不可逆节点能被触发。
- 不可逆节点能改变变量、卡牌状态或后续风险。
- 推进回合后能看到明确的时间推进报告。
- 情报卡至少能揭示 5 个变量或变量区间。
- 结局报告能展示至少 3 条关键因果链。
- 结局报告能展示至少 2 个错过窗口。
- 一局可以正常跑到第 12 回合并触发结局。
- `npm test` 通过。
- 新增 JSON 引用能通过验证脚本。

## 18. 最终产品判断

v0.2 的重点不是让内容变多，而是让系统变紧。

程序要让规则真的收紧：

- 窗口关闭
- 卡牌过期
- 节点锁死
- 变量反噬
- 结局可解释

美术要让玩家看见它正在收紧：

- 倒计时
- 红线
- 锁章
- 档案翻页
- 历史事故报告

如果玩家在推进回合前产生犹豫，在不可逆节点触发后产生后悔，在结算报告里理解自己如何一步步走向结果，v0.2 就达成目标。
